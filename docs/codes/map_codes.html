Scaling CLI code map

Guide to the codebase behind the HerdSim scaling campaigns: where the CLI lives, which files and functions each research question uses, and how a protocol YAML becomes trials, merges, and analysis packages.

1. Overview

Scaling experiments are not a separate simulator. They reuse the same SimulationRunner stack as the interactive UI and benchmarks. The scaling layer only orchestrates grids of cells (N, D, layout, seed, optional info factors), writes ledgers, and runs analysis packages on the resulting CSVs.

Entry points: make -C scaling <target> wraps scaling/scripts/campaign.py, which loads a protocol YAML under scaling/configs/protocols/ and dispatches to a runner script.

What scaling owns

  • Protocol YAMLs and canonical grid
  • Multiprocess grid / factor runners
  • Claim / T1 window planners
  • Manifest resume ledger + trials.csv
  • Analysis exports under analysis/scaling/

What it borrows from core

  • core/simulation_runner.py
  • core/methods.py method bundles
  • Sheep / dog / observation plugins
  • drive_to_goal scenario
  • Metrics registries

4. One simulation tick (every trial)

Every scaling cell ends in runner._run_cell, which builds a config via resolve_experiment_config and steps SimulationRunner until success or timeout.

_run_cellservices/scaling/runner.py
->
get_methodcore/methods.py
->
resolve_experiment_configcore/experiment_config.py
->
SimulationRunnercore/simulation_runner.py
state(t)
  -> environment updates / failure factors
  -> sheep_dynamics.step
  -> observation_model.observe_all
  -> (optional) communication messages
  -> dog_controller.step(observations)
  -> robot constraints / walls
  -> metrics + history recorder

Resume identity is _cell_key(ScalingCell) stored in manifest.jsonl. Completed status=ok keys are skipped on re-run.

8. How to trace one research question

  1. Find the RQ in the phase table above and open its protocol YAML under scaling/configs/protocols/.
  2. Note runner (grid vs factor), output, upstream_protocol, and grids.
  3. Follow the matching make target in scaling/Makefile into campaign.py.
  4. For sims: land in runner._run_cell -> method bundle -> sheep/dog plugins.
  5. For analysis: land in analysis/scaling/ package module and the claim folder packages/.
  6. Cross-check the human narrative under scaling/docs/report/rq*/ and the tracker.
# Example: RQ2 scout
make -C scaling scaling-scout WORKERS=16
# protocol: scaling/configs/protocols/phase1_scout.yaml
# code: campaign.run -> run_grid.main -> run_scaling_grid -> _run_cell
# out:   scaling/results/phase1/scout/trials.csv
