# Package F: phase1_claim

Package F fits scaling curves to the `D_min` frontier (power vs piecewise and related models) and compares them with leave-one-N CV (feeds C6a/C6b).

`best_model=piecewise by leave-one-N RMSE` means: among the curves tried for `D_min` vs flock size N, piecewise had the lowest leave-one-N RMSE, so it wins that comparison. 

Leave-one-N fits on all N except one, predicts the held-out N's `D_min`, and repeats for every N; 

RMSE (Root Mean Square Error) is the square root of the average squared prediction mistakes, i.e. how far those predictions miss (lower is better). 

On this export: power RMSE about 0.247, piecewise about 0.132. That is the evidence behind C6a (power fits worse than piecewise). The piecewise fit here is basically a two-level step (`D_min` = 2 then 1 around N=10), so treat C6a as weak, not a rich scaling law.

`prefers_piecewise_or_state=True` follows from that RMSE win for piecewise. `state_models=[]`: no per-layout state curves were fitted in this export.

## Files from this run

Auto-generated by the campaign / analyse:

- `artefacts.json`: Stores a map of artefact names to absolute paths (and any package summary fields) produced by analyse. Purpose: machine-readable index of what this export wrote.
- `delta_aic_vs_power.csv`: Stores AIC (or delta-AIC) of alternate models relative to power. Purpose: secondary model-comparison table beside `scaling_fits.csv`.
- `frontier.csv`: Stores per (layout, N) frontier fields: `D_min`, `D_overcrowd`, `D_max`, cheap-good `B*` (dogs/time/effort), and hard_failure. Purpose: fewest-dogs edge and overcrowding onset.
- `provenance.json`: Stores git commit, host/platform, timestamps, and protocol snapshot for this analyse export. Purpose: tie the package tables to a code version and run.
- `scaling_cv.csv`: Stores leave-one-N-out RMSE (or similar) per model family. Purpose: decide C6a (power vs piecewise) without refitting by hand.
- `scaling_fits.csv`: Stores fitted scaling models (constant/linear/power/piecewise) with params, RMSE, AIC, BIC. Purpose: compare which curve family describes `D_min` vs N (feeds C6).
